# Schritt-für-Schritt-Migration: Supabase → Railway + OAuth2-Proxy

## 1. Railway Postgres deployen
- DB-URL und SSL konfigurieren
- Tabellen / Migrationen übernehmen
- RLS prüfen → ggf. Claims-Feld anpassen

## 2. OAuth2‑Proxy deployen
- Docker-Container mit Google OIDC konfigurieren
- Redirect URLs, Client ID/Secret, Cookie Secret setzen

## 3. Backend anpassen
- Supabase-JWT-Checks entfernen
- Header oder OIDC-Tokens prüfen
- Claims für RLS setzen (`SET LOCAL request.jwt.claims`)

## 4. Frontend anpassen
- Supabase-Login entfernen → Redirect auf Proxy
- Cookies/Header für Auth im Backend nutzen

## 5. CI / Deployment anpassen
- Secrets für OIDC, DB setzen
- Env-Vars aktualisieren
- Tests anpassen (JWT von Proxy statt Supabase)

## 6. User-Migration entscheiden
- Mapping bestehender Supabase-User auf neue User-IDs
- Oder Neustart → neue User bei erstem Login
